## Why it matters

**Why do this?**

Three of the five commits are refactors, and they are one piece of work: RepoTab
and App.tsx had grown into files where adding a preference meant editing four
places and adding a staging write meant reading a thousand lines to find the
three that mattered. The two features either side of them are about a repository
opened from the command line landing where the user already is, and about a
remote address being right rather than plausible.

**What problem does it solve?**

`gitty <repo>` used to start a second application, so a day's tabs scattered
across windows. The ssh-alias bug produced a URL that looked like a link and
went nowhere — the alias git stores verbatim is not a host. The refactors solve
nothing visible on purpose: the chunks came out byte-identical apart from the
shell, and storing, loading and Restore Defaults were each checked against a
running app.

**What does it affect?**

The single-instance setting is the documented exception to preferences living in
the renderer, written into CLAUDE.md and `ref/spec/main-process.md` so the next
one is not put there by imitation. `remote.ts`, `remoteCache.ts` and
`sshconfig.ts` are pinned by 129 new lines of `test/remote.test.ts`. And
CLAUDE.md gained the rule the staging split cost: an inactive tab keeps its DOM,
so a snippet driving the UI must start from the visible `.repo-tab-shell` or it
clicks into another repository.
