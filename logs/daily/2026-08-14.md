## Why it matters

**Why do this?**

An external review named six gaps, and the plan written that morning
(`ref/plan/2026-08-14-external-review.md`) is what the rest of the day works
through. Reading history was solid; acting on it was not — there was no way to
decide which changes are one commit, no way to search the repository rather
than the loaded page of commits, no packaged build, and no automated check
beyond the compiler.

**What problem does it solve?**

Staging closes the largest gap without adding a commit box: the index is
curated in the panes that already display the work, and the message is left to
an agent in a terminal where a real tty exists. Pickaxe search, `git grep` and
`git log -L` answer questions the filter box could not. Lanes make a merge's
origin visible. The web server's token closes a hole that loopback alone never
covered — any page in this machine's browser could fetch the port and read
every open repository.

**What does it affect?**

`src/main/patch.ts` is the risky part and is deliberately pure string work, so
`test/patch.test.ts` can pin it: a wrong patch does not throw, it writes a wrong
index silently. That reasoning, along with the token, the search machinery and
the lane fold, is recorded in CLAUDE.md so the constraints survive the session.
Packaging turns the project into something installable rather than a
`run.sh` away, and 0.1.6 ships on top of it.
