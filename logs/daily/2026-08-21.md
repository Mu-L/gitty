## Why it matters

**Why do this?**

Semantic reading arrived as core code, and it should not have: it is one
opinionated feature among many that a history browser does not need. Extracting
it forced the question of what a plugin is here, and the answer became a spec
rather than a convention.

**What problem does it solve?**

It keeps the core small while leaving room for features that only some users
want — a plugin owns both halves of the process boundary and adds nothing to the
shared types, the core message tables or SettingsPane. Separately, the log pane
stopped misleading: rows that read out of order, a rebase that hid what it
rewrote and a history measured from the wrong column were all quiet wrongs, not
crashes.

**What does it affect?**

`src/plugins/` and its two registries are now the way non-core work is added;
`ref/spec/plugins.md` and `ref/spec/semantic-reading.md` say how. The log,
history and layout fixes ship in 0.2.0, whose README and eight manual
translations were brought current with the English.
