## Why it matters

**Why do this?**

Rendering HTML is the natural extension of the markdown preview — someone
browsing a repository's .html files should see the page, not only the markup
behind it. The binary-resolution bug was a post-release regression: on macOS
the old logic looked in the wrong place and started a fresh download instead of
using the binary already installed.

**What problem does it solve?**

An HTML file opened in Gitty showed raw markup even when the file was a
complete page in its own right. The preview means no round trip to a browser to
see what it looks like. The resolution fix removes a start-up failure macOS
users would otherwise hit.

**What does it affect?**

HtmlPane follows the path MarkdownPane already laid down (isXxxPath → component
→ a toolbar toggle → its message-table strings), which widens Gitty's reach as a
general file viewer. Documenting `setup.sh`'s shortcut and `run.sh`'s start-up
sequence also makes packaging and distribution behave predictably.
