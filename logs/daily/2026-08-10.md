## Why it matters

**Why do this?**

The work tree pane could copy, open and blame a file, but the one action a
work tree invites — throwing a file away — still meant leaving for a shell.
And once a change was staged, the single-character index column was the only
signal saying so.

**What problem does it solve?**

Deleting now happens in-app: a native dialog asks first, then the file goes to
the system trash, recoverable outside git as well as in it; where no trash
exists, a second dialog says plainly that the file leaves the disk before the
unlink. Staged state is visible down the whole tree instead of one column
wide, and the re-parent guard stops the shell pane from stealing the caret
mid-type on every refresh.

**What does it affect?**

Both behaviours are work-tree features, so commits and snapshots — where there
is nothing on disk to delete or stage — are untouched. The delete dialog
threads a batch of new strings through all nine message tables, and the
terminal fix makes continuous use of the shell pane far less jarring.
