## ウィンドウ <a id="the-window"></a>

中央に 4 つのペイン、その上にタイトルバー、下にタブバー。

### タイトルバー <a id="title-bar"></a>

左から右へ、まず現在のリポジトリを説明し、それから操作します:

- **Gitty** — 左端のアイコンと名前で **About** ダイアログを開きます。バージョン、ビ
  ルド時刻、作者、Electron・Chromium・Node のバージョン、そしてホームページへのリン
  クが出ます。
- **‹ › ▾** — このリポジトリでこれまでどこを見てきたか。[戻る・進む](#going-back)を
  参照。
- **リポジトリのパス**はボタンで、[最近のリポジトリ](#recent-repositories)メニューを
  開きます。
- その隣の **+** — ディレクトリ選択ダイアログ。選んだリポジトリを新しいタブで開きます
  (<kbd>Ctrl+O</kbd>)。リポジトリのボタンの隣にあるのは、両者が同じ主題 — どのリポジ
  トリを見ているか、別のものを開くか — だからです。
- **⎇ ブランチ**もボタンです — git がチェックアウトしているブランチを示し、読むため
  の他ブランチのメニューを出します。[別のブランチを閲覧](#browsing-another-branch)を
  参照。
- **`origin/main ↑2 ↓0`** — チェックアウト中のブランチの上流と、その先行・遅れの
  数。追跡していないブランチでは表示されません。
- **`3 changed`** — ワークツリーで未コミットのファイル数。コミットペインの
  **Working Tree** 行が持つ数と同じものです。
- **Panes ▾** — 4 つのペインの表示・非表示。
  [全画面と非表示](#full-screen-and-hiding)を参照。
- **Settings** — 設定ダイアログ ([設定](#settings))。<kbd>Ctrl+,</kbd> でも開きま
  す。
- **Refresh** — ステータスとログを手動で読み直します (<kbd>F5</kbd> /
  <kbd>Ctrl+R</kbd>)。Gitty はリポジトリを監視して自動で更新するので、これは監視が気
  づけない場合のためのものです。

別のブランチを見ている間、ブランチボタンは `⎇ main › other-branch` と表示され、直前
の git コマンドのエラーは数値の隣に赤字で出ます。

### 戻る・進む <a id="going-back"></a>

履歴を読むということは彷徨うことです。あるコミット、その中のあるファイル、ログを 2
ページ進んだ先の別のコミット、そしてまた最初のコミットへ。タイトルバー左端の 3 つの
ボタンは、ブラウザと同じようにその彷徨いを記憶します。

- **‹** (<kbd>Alt+←</kbd>) はいま見ている場所の前に見ていた場所へ戻り、**›**
  (<kbd>Alt+→</kbd>) はそこから離れた場所へ再び進みます。どちらも行き先が無ければ灰
  色になり、ホバーするとその行き先の名前が出ます。
- **▾** は場所そのものを新しい順に一覧し、現在地に点が付きます。どれかを選べばそこへ
  直接ジャンプします。

*場所*とは上の 2 つのペインが表示していたものすべてです。ビュー — ワークツリー、1 つ
のコミット、2 つのコミットの範囲、スナップショット — 、その中で選ばれているファイル、
そして差分の隣に開かれたドキュメント。ですから各地点は `Working tree`、
`7bb7787 — Refresh screenshot batches`、`src/main/git.ts @ 7bb7787` あるいは
`blame: src/main/git.ts @ 7bb7787` と読め、そこへ戻ればコミットを選び直すだけでなく同
じファイルが同じリビジョンで画面に戻ります。

履歴はウィンドウではなくリポジトリに属します。各タブは直近 50 件の場所を覚え、タブを
切り替えればボタンが辿る場所も切り替わります。再起動をまたいでは保持されません。

### タブ <a id="tabs"></a>

下端のタブバーが開いているリポジトリをすべて並べます — ベース名、ワークツリーに未コ
ミットの変更があるときの黄色い点、そして閉じる **×**。この点は `git status` が報告す
るもの全部を数え、追跡されていないファイルも含みます。そして真価を発揮するのは、いま
見ていないタブの上です。アクティブなリポジトリはタイトルバーに既に `3 changed` と出
ていますが、背面のタブは完全に隠れているので、この点だけが「あちらにまだ仕事が残って
いる」という唯一の合図になります。タブにカーソルを合わせると、リポジトリ名とその旨が
言葉で出ます。

**+** (および <kbd>Ctrl+O</kbd>) は別のリポジトリを新しいタブで開きます。タイトルバー
は常にアクティブなものを示します。各タブは自分のペインとターミナルを保持するので、読
みかけのコミットも走らせたままのシェルも、切り替えて戻ってきたときそのままです。最後
のタブを閉じると、次のリポジトリを開くボタンだけの空のウィンドウが残ります。(開いてい
るタブは再起動をまたいで記憶されません。)

### 最近のリポジトリ <a id="recent-repositories"></a>

タイトルバーのリポジトリパスは、以前に開いたリポジトリのメニューです — ベース名と親
ディレクトリ、新しい順。

- **クリック** — 新しいタブで開く。
- **Ctrl/Cmd+クリック**または**中クリック** — 現在のタブで開き、そこのリポジトリを置
  き換えつつ、バー内でのタブの位置は保つ。
- **右クリック** — その項目を一覧から削除。メニューは開いたままなので、続けていくつも
  消せます。

その下に **Open Repository…** と **Clear Recent** があります。一覧は
`~/.config/Gitty/recent-repos.json` にあり、12 件を保持し、移動・削除されたものは飛ば
します。

### 全画面と非表示 <a id="full-screen-and-hiding"></a>

どのペインのヘッダーも同じ 2 つのコントロールを持ちます。左端の **⤢** がそのペインで
ウィンドウを埋め、右端の **×** がそれを隠します。

全画面はタイトルバーとタブバーを含む他のすべてを覆いますが、下のペインは動き続けま
す — ターミナルは覆われている間も走り続けます。同じ角の **⤡**、<kbd>Esc</kbd>、ヘッ
ダーのダブルクリック、あるいは <kbd>Ctrl+Shift+1</kbd> … <kbd>Ctrl+Shift+4</kbd> でレ
イアウトが戻ります。全画面になれるのは一度に 1 つだけです。

非表示は逆方向で、どのペインも片付けて呼び戻せます:

- タイトルバーの **Panes** が 4 つすべてを並べ、表示中のものには点が付きます。クリッ
  クで切り替わり、**Show All Panes** が 4 ペインのレイアウトを復元します。
- <kbd>Ctrl+1</kbd> … <kbd>Ctrl+4</kbd> がこの順に Files、Diff、Commits、Terminal を
  切り替えます。
- <kbd>Ctrl+Shift+0</kbd> は 4 つすべてを一度に戻します。4 つの各トグルキーの 1 つ
  先、0 で「全部」です。Shift が付くのは、<kbd>Ctrl+0</kbd> がブラウザエンジンのズー
  ムリセットで、View メニューがそれを保持しているからです。

残ったものがウィンドウを分け合うので、コミットペインを隠せば差分が全高を得ます。最後
に残った 1 つのペインには **×** がありません — 空のウィンドウでは押すものが無くなるか
らです。非表示の状態は再起動をまたいで記憶され、ターミナルペインは片付けられるだけで
決して閉じられません。シェルは走り続け、戻るときスクロールバックごと戻ってきます。

## 各ペイン <a id="the-panes"></a>

### Working Tree (左上) <a id="working-tree-top-left"></a>

変更されたファイルを折りたためるツリーで表示し、名前の横に行数を添えます。リポジトリ
全体 — ワークツリーまたはコミットのスナップショット — を閲覧するときは、すべてのディ
レクトリが閉じた状態で開きます。それは読むべき変更のリストではなく、潜り込むべきツ
リーだからです。変更のリストは展開した状態で開きます。どの階層でもディレクトリはファ
イルより前に来て、各グループ内の名前はバイト比較ではなく読者が期待する順で並びます。
名前の中の数字は数値として扱うので `W9` は `W10` の前に来て、大文字小文字は第一義で
はないので `butler/` はすべての大文字の後ではなく b の並びに置かれます。
ステータスは 2 列 — ステージ済みの状態 (緑) とワークツリーの状態 (黄 / 赤)。追跡され
ていないファイルは `??` です。行数はワークツリーではディスクから、それ以外ではそのリ
ビジョンから数えます。バイナリファイル、削除されたファイル、8 MB を超えるものには表
示されません。その後にチャーン（churn）が続きます。その変更がそのファイルで何行を追加
し何行を削除したか、`+12 −3` の形で、ワークツリーでは HEAD との差分、コミットや範囲で
は親コミットとの差分です。スナップショットは変更ではなくツリーなのでチャーンはありま
せん。バイナリファイルや、統合差分が誰のものでもないマージコミットも同様です。

- **クリック** — そのファイルの差分を右に表示。
- **ダブルクリック** — ファイル全体を差分の隣にドキュメントとして開く。行番号とシンタッ
  クスハイライト付き (Markdown なら描画済みのドキュメント、画像なら画像そのもの)。
- **ステータス列をクリック** — そのファイルをステージする。ステージ済みならアンステー
  ジする。
- **右クリック** — View File、Open in System App、Reveal in File Manager、Copy
  Relative Path、Copy Absolute Path、Copy File Name、Blame File、File History、
  Stage / Unstage File、Discard Changes、Delete File。
- **フォルダをクリック** — 折りたたみ / 展開。

**Discard Changes** はファイルをインデックスが持つ状態へ戻します。その前に、やり直し
が利かないことを率直に告げるネイティブの確認が出ます。追跡されていないファイルには戻
すべきインデックス版が無いので、代わりに **Delete File** を出し、システムのゴミ箱へ
送ります。

ヘッダーの **Send to agent** はインデックスを手渡します。右下ペインのシェルへコマンド
を打ち込んで Enter を押すだけです。Gitty の内部でモデルが呼ばれることはなく、あなたが
送らなかったものはマシンを離れません。エージェントのプロンプトと出力はターミナルに出
ます。そこには本物の tty があるので、hooks や gpg 署名はいつも通りに動きます。

ボタンの隣の矢印がコマンドを選ぶ場所です — 設定項目はありません。これはインストール
ごとに一度ではなく、受け渡しのたびに一度問われる質問だからです。ドロップダウンは
Gitty が覚えているコマンドを並べ、ボタン自身が実行するものにチェックを付け、選んだも
のを実行します。項目の右端の **×** が、確認の後にそれを一覧から外します — 一覧はコマンドが書き留められる唯一の場所で、メニューは開いたままなので、続けていくつも外せます。最下部の **New command…** は 1 行の
ボックスを開き、現在のコマンドを事前入力した状態で、一覧に無いものを入れられます。一
覧はいくつかの候補から始まり — どのエージェントがインストールされているかは Gitty に
は知りようがありません — コマンドは実行されたことで一覧に加わるので、打ちかけの行が
記憶されることはありません。

コミットログのワークツリー行を右クリックすると、別ウィンドウでの会話のための
**Copy Staged Diff** も出ます。

コミットやコミット範囲を選ぶと、このペインは代わりにそのコミットのファイルを並べま
す。**Back to Work Tree** (または <kbd>Esc</kbd>) でワークツリーへ戻ります。
[スナップショット](#snapshots)では、変更分だけでなくそのコミット時点のツリー全体を並
べます。

### Diff (右上) <a id="diff-top-right"></a>

新旧の行番号、hunk ヘッダー、追加 / 削除の色分けを備えた unified 差分を、ファイルの
リストとして並べます。各パスは全幅の見出し、hunk ヘッダーは淡色 — それは行範囲であっ
て真っ先に見るものではないからです — リネームは `old → new` と読めます。ファイルを選
んでいなければ全部を一度に表示します。ワークツリーの未コミット変更すべて、あるいは選
択したコミットの全ファイルです。

- **Show Whole Diff** — ファイルを選んだ後、その統合差分へ戻ります。ヘッダーに常駐
  し、いま画面に出ているのが差分全体であるときは点灯します。ワークツリー版はステージ
  済みと未ステージの変更をまとめて扱い、`git diff` だけでは漏れる追跡外ファイルも
  インライン展開します (50 件まで、その先は通知)。
- **Wrap** — 横スクロールの代わりに長い行を折り返します。既定でオン。
- **Inline / Side-by-Side** — `+`/`-` 記号付きの 1 列か、新旧を左右に並べるか。後者
  では削除の連続とそれに続く追加が組にされます。折り返された左右は揃ったままです。
- **ファイル見出し** — 各見出しが自分のファイルを畳みます。三角形で名前だけに縮み、
  ヘッダーの **Collapse All** / **Expand All** が一括で行います。見出しを
  **Ctrl+クリック**するとそのファイルが新しいドキュメントタブで開き、右クリックで
  **Open in a New Tab**、**Select in the File List**、各種パスのコピー、そして — ディ
  スク上のファイルが表示中の版そのものであるワークツリーでは — **Open in System App**
  と **Reveal in File Manager** が出ます。リネームは新しいパスを開きます。
- **Stage / Unstage** — 差分が追跡済みの 1 ファイルの作業である間、各 hunk ヘッダー
  にボタンが付き、その hunk をインデックスへ入れるか、取り戻します。先に行を選んでお
  くとボタンは **Stage 3 lines** になります。選ばれていない追加行はパッチから外され、
  選ばれていない削除行は文脈行に降格され、hunk ヘッダーは再計算されます — ファイル全
  体が目の前にあるウィンドウで、`git add -p` が作るのと同じ分割です。選択範囲は通常の
  テキスト選択なので、ドラッグは相変わらずコピーです。2 つの hunk にまたがる選択は、
  それぞれにその部分を与えます。
- **Unstaged / Staged** — ファイルがインデックスのどちら側から読まれているか。両側に
  何かあるときに表示されます。ステージングは画面に表示中の側に作用します。バイナリ、
  モード変更、リネームには選べる hunk が無く、ファイルリストから丸ごとステージされま
  す。**Ignore whitespace** がオンの間は hunk ボタンも消えます。その差分は適用する変更
  をすべて保持しているわけではないからです。
- **右クリック** — Copy Selection、Copy Whole Diff、および同じトグル群。

行全体より語単位のほうが読みやすい場合、変更行の中で変わった語が強調されます。
[設定](#settings)の **Word highlight** です。

設定は実行をまたいで記憶されます。行は 1500 ずつのかたまりで描画されスクロールに応じ
て伸びるので、大きなコミットでも軽快です。2 MB を超える差分は通知付きで切り詰められ
ます。

### ファイル全体を見る <a id="viewing-files"></a>

既定で表示されるのは差分ですが、どのファイルも丸ごと開けます。ツリーで**ダブルクリッ
ク**するか、ヘッダーの **View File** / **Preview** を使うか、差分の中のファイル見出し
を **Ctrl+クリック**するか、どちらかのコンテキストメニューから選びます。

ファイルは差分の上にではなく*隣*のタブ列に独立したドキュメントとして開くので、いま見
ている差分を失わずにファイルを読めます。**Diff** タブは常に先頭にあり、ツリーでのシン
グルクリックはこれまで通りその場で差分を辿ります。各ドキュメントは開いたときのリビ
ジョンを覚え、自分の **×** で閉じ、リポジトリが変わればワークツリーのファイルを読み
直します。ソースファイルには行番号とシンタックスハイライトが付き、Markdown は
[描画された状態](#markdown-preview)で開いてソースへ切り替えられ、HTML は
[同じく描画された状態](#html-preview)で開き、画像は [画像そのもの](#images)として開
きます。

どのリビジョンが得られるかはペインに従います。ワークツリーではディスク上のファイル、
それ以外では選択中のコミット時点のファイルです。ドキュメントを開くのはモードではなく
動作です — 別のファイルや別のコミットを選べば差分が戻ります — なので、変更を見たいと
きにペインがファイル表示のまま動かなくなることはありません。

#### スナップショット <a id="snapshots"></a>

コミットを右クリックして **Browse Snapshot** を選ぶと、そのコミット時点のリポジトリを
読めます。左上のペインはそのコミットが触れたファイルではなく*ツリー全体*を並べ、どの
ファイルを選んでもそのリビジョンで開きます。スナップショットには見せる差分がないの
で、そこではすべてのファイルがドキュメントです。

スナップショットのファイルはそのリビジョンにおいてディスク上に存在したことがありませ
ん。だから **Open in System App** は一時コピーを渡し、**Reveal in File Manager** はそ
もそも提供されません。**Back to Work Tree** (または <kbd>Esc</kbd>) で抜けます。

#### Markdown プレビュー <a id="markdown-preview"></a>

`.md` ファイルを選ぶと **Preview** ボタンが増えます — 既定はオフなので、頼むまで差分
は差分のままです。ファイルを丸ごと描画します。ワークツリーではディスク上の版、それ以
外では選択中のコミット時点の版です。

言語が指定されたフェンス付きコードブロックはシンタックスハイライトされ、YAML フロント
マターは抜き出されて独立したハイライト済みブロックとして表示され、見出しレベル、リス
トの記号、リンク、インラインコードは色分けされて構造が一目で読めます。

- **Wrap** — 差分と同じトグルで、既定はオン。地の文は常に折り返します。プレビューでは
  このトグルが、フェンス付きコードブロック・幅広の表・長いインライン文字列も折り返す
  か、それとも横スクロールにするかを決めます。
- **Outline** — ドキュメントの脇に見出し構造をレベルごとに字下げして表示し、スクロール
  した先の見出しに追従します。項目をクリックすると飛べます。ドキュメントとの間の仕切
  りをドラッグすると、どちら側にも広いスペースを割けます。この幅はリポジトリ内のすべ
  てのドキュメントで共有され — 特定のファイルの属性ではなく、読むときの好みです — 他
  のペインのサイズと同様、ウィンドウが続く限り保持されます。
- **Source lines** — 既定はオフで、[設定](#settings)でオンにします。見出し・段落・リ
  スト項目・表・フェンス付きブロック・画像のすべてが、ソースで始まる行番号を左のガ
  ターに表示します。番号は挿入ではなく描画されるので、コピーする選択範囲にも
  <kbd>Ctrl+F</kbd> の検索対象にも入りません。文中に書かれた画像は自分用の行を持たな
  いので、その段落の行番号を取ります。
- **<kbd>Ctrl+F</kbd>** — ドキュメント内を検索。[テキストの検索](#finding-text)を参
  照。
- **右クリック** — Copy Selection、Copy Markdown Source、折り返しとアウトラインのトグ
  ル、そして Show Diff Instead。

Markdown 中の生 HTML は描画されず、ウェブへのリンクはアプリ内ではなくシステムのブラウ
ザで開きます。リポジトリ内の別ファイルへのリンク — `ref/readme/manual.md`、
`../README.md`、`/CHANGELOG.md` — はその代わりにここで辿られます。**Ctrl/Cmd+クリック**
がそのファイルを diff の隣に独立したドキュメントとして、リンクを持つドキュメントと同じ
リビジョンで開くので、古いコミットで読んだ README はそのコミットのファイルへ導きます。
末尾の `#fragment` も一緒に運ばれ — `manual.md#the-window` は forge 上と同じようにその
見出しでマニュアルを開きます — このドキュメントに無い見出しは単に先頭で開きます。その
ようなリンクにカーソルを合わせるとそう告げます。普通のクリックは以前と同様何もせず、
リポジトリのルートを越えて外へ登るリンクはこの類いではありません。ドキュメントからの
相対パスで書かれた画像はリポジトリから読み出されます — ドキュメントと同じリビジョン
なので、古いコミットは当時のスクリーンショットを見せます。そのリビジョンに無いものは
alt テキストを添えた破線のプレースホルダーになります。ウェブ上の画像は一切取得しませ
ん。他人の README を読むのに、その相手のホストへ挨拶しに行く必要はありません。

![Markdown プレビュー](../../ref/gitty-0.1.5-markdown.png)

#### HTML プレビュー <a id="html-preview"></a>

`.html`、`.htm`、`.xhtml` のファイルにも同じ **Preview** ボタンが付き、ドキュメントは
ソースとしてではなく描画されて表示されます — ワークツリーではディスク上の版、それ以外
では選択中のコミット時点の版です。

`srcdoc` を通じて読み込まれるサンドボックス化されたフレームで描画されるので、ページが
アプリを自分自身から離れたところへナビゲートすることは決してありません。ドキュメント
自身のスタイルシートが効きます — レイアウト、色、フォントはそのドキュメントのもので
す。スクリプトは実行されず、リモートの画像も取得されません。フレームはアプリのコンテ
ンツセキュリティポリシーを継承しており、そのどちらも許可しないからです。ページは実行
されるのではなく、表示されます。**Wrap** が、フレームが自分でスクロールするか、コンテ
ンツまで伸びてページ全体が一体としてスクロールするかを決めます。<kbd>Ctrl+F</kbd> と
<kbd>Ctrl+Shift+C</kbd> はフレーム内で効きます。フレームのキーはウィンドウの残りに
は届きません。

#### 画像 <a id="images"></a>

`.png`、`.jpg`、`.gif`、`.webp`、`.bmp`、`.ico`、`.avif`、`.svg` は「バイナリです」と
いう報告ではなく画像そのものとして開きます — ワークツリーではディスクから、それ以外で
はコミットから。市松模様の上でペインに合わせて表示されるので、透明は透明として読めま
す。**クリック**すると実寸になりスクロールでき、もう一度クリックすると再びフィットし
ます。ピクセル寸法とディスク上のサイズが下に出ます。12 MB を超える画像はインライン展
開されません。

![画像プレビュー](../../ref/gitty-0.1.5-image.png)

#### Blame とファイル履歴 <a id="blame-and-file-history"></a>

ツリー内のファイルを右クリックして **Blame File** か **File History** を選ぶと、どち
らも差分の隣にドキュメントとして開きます。Blame はソースの行ごとに 1 行 — コミット、
作者、日付、行そのもの（まだコミットされていない行は em dash）、コードビューアのよう
にハイライトされて — を表示中のリビジョンで示します。File History はそのファイルに触
れたすべてのコミットをリストし、リネームを追跡し、コミットをクリックすればそれを開き
ます。

blame の行を右クリックすると **History of These Lines** が出ます。選択範囲が覆う行 — 選
択が無ければクリックした行 — に対して `git log -L` を実行し、それが独立したドキュメン
トとして開いて、それらの行に触れた各コミットと、それが行に対して何をしたかを示します。
Blame は*最後に誰が*を答えます。こちらは*どうしてこうなったか*を答えます。範囲はリ
ネームをまたいで自分で追跡します。

#### リポジトリを検索 <a id="searching-the-repository"></a>

ワークツリーペインのヘッダーにある **Search** が、ファイルリストの上にボックスを開い
て `git grep` を実行します。結果はファイルごとにまとめられたドキュメントで、行番号が
左に下ります。1 つクリックするとそのファイルがその行で開き、行が印されます。

検索は画面のリビジョンに従います。ワークツリーではディスク上の内容 — 未コミットの作業
も含めて — を読み、コミットやスナップショットではそのリビジョンを読みます。ボックスが
どちらかを示します。2000 件を超えるヒットは、大きすぎる差分と同じように、止まってそう
告げます。パターンは単一の引数として git に届くので、正規表現が途中で食われることはあ
りません。

### Commits (左下) <a id="commits-bottom-left"></a>

現在のブランチのログ。300 件ずつ読み込み、スクロールに応じて伸びます。先頭行は
**Working Tree** — 未コミットの変更で、変更ファイル数付き。選ぶと上の 2 ペインがワー
クツリーに戻ります。ログの上にあるフィルターボックスで一覧を絞り込めます。入力はデバ
ウンスされ、✕ でクリアでき、結果も同じくページ送りされます。

ヘッダーの **Graph** がハッシュの横にレーン (lane) を描きます。ブランチがどこで分かれ、
マージがどこに着地し、コミットがどの線に属するか。それは `git log --graph` を解析する
のではなく — あの ASCII はターミナル向けに組まれています — 各コミットの親から計算され
ます。レーンはページを下る間自分の色を保ち、パレットは固定です。SHA から色を導いて
「誰か」を表す blame とは意図的に異なります。10 レーンを超えると、あふれた分が最後の
列を円で囲んで共有するので、多数のヘッドを持つリポジトリでも件名がペインから押し出さ
れることはありません。**All Branches** はすべてのブランチを一度に表示します
(`git log --all`)。これで 2 つのブランチの関係が見えます。ブランチメニューは依然とし
て 1 つずつ読みます。

隣のドロップダウンは何を検索しているかを示します:

| | |
| --- | --- |
| **Message / Author** | コミットメッセージと作者。大文字小文字を区別しません。既定。 |
| **Content** | git の `-S`。テキストの*出現回数*が変わったコミット — 導入されたか削除された場所。リテラルなので、`.` や `(` だらけの検索はそれらの文字を意味します。 |
| **Content regex** | git の `-G`。差分がその式に一致するすべてのコミット。行を動かしただけのものも含みます。 |

この 2 つの内容モードは blame が答えられない問い — *どのコミットがこの行を導入したか*
— に答え、そのために履歴の全差分を読むので、実行中はボックスが検索中だと示します。テ
キストやモードを変えると進行中の検索が止まります。コマンドラインへ何かを繋ぎ込むこと
はなく、正規表現は 1 つの引数として git に届きます。

- **クリック**または <kbd>Enter</kbd> — そのコミットを表示。ファイルが左上、完全な差
  分が右上を埋めます。コミットの件名、作者、日付、本文がファイルリストの上の帯に表示
  されます。本文が長いときは ▸ トグルで折り畳めるので、ファイルリストが場所を保てま
  す。
- **Ctrl+クリック** (macOS では <kbd>Cmd</kbd>)、<kbd>Shift+クリック</kbd>、
  <kbd>Space</kbd> — 2 つ目のコミットを選び、古い方を先にして両者を比較。
- **↑ ↓ / j k / PgUp / PgDn / Home / End** — カーソル移動。
- **右クリック** — 差分を表示、ハッシュ・短縮ハッシュ・件名をコピー、
  [スナップショットを閲覧](#snapshots)、あるいは選択中のコミットと比較。
- **右クリック → Open in Browser** — このコミットをシステムのブラウザで描画。
  **Copy Commit URL** はリンクをコピーします。アプリ内の Web サーバーが、開いている各
  リポジトリを辿れるコミット一覧として提供します — コミットペインの **Open in
  Browser** ボタンはそこへ着地します — 各コミットのメタデータ、ファイル、差分があり、
  ファイル単位の差分もワンクリックです。

  待ち受けるのは `127.0.0.1` ですが、それだけでは大したことになりません。ループバック
  が締め出すのは他のマシンであって、あなたのブラウザ内の他のページではありません。そ
  のどれでもこれを取得できてしまいます。そこで各 URL は起動時に生成されメモリに保持さ
  れるトークン — `/t/<token>/…` — を持ち、Gitty が渡すリンクには既にそれが含まれてい
  ます。誤ったトークンは 403 ではなく 404、`Host` がループバックでない要求は拒否され
  (DNS リバインディングが無意味になるのはこのためです)、ページは
  `Referrer-Policy: no-referrer` で配信されるので、コミットメッセージからリンクを辿っ
  てもトークンは持ち出されません。トークンは起動ごとに新しいので、URL はこのセッション
  の実行中だけ有効です。
- 左上のペインでファイルを選ぶと差分がそのファイルに絞られ、**Show Whole Diff** でま
  た広がります。

![任意の 2 コミットの差分](../../ref/gitty-0.1.5-range.png)

#### Gource <a id="gource"></a>

[gource](https://gource.io/) が `PATH` 上にあれば、コミットペインの
**Open in Browser** の隣に **Gource** ボタンが現れます。リポジトリの履歴をアニメーショ
ンとして再生します — ディレクトリツリーが育ち、コミットが着地するたびにファイルが光
り、ログにある名前ごとに作者がその間を飛び回ります。Gource は独自のウィンドウを開き、
Gitty を閉じた後も動き続けます。ボタンは起動したことを確認できるだけ待ち、起動できな
ければ gource の言ったことを表示します。

履歴の 1 日を 0.5 秒で再生し、アイドル状態のファイルはスクリーンに残し、長い空白はス
キップします。これによって実際のリポジトリが遅いしずくではなく読めるものになります。
何かをインストールすることはありません。gource が `PATH` になければ、ボタンは単に存在
しません。

#### 別のブランチを閲覧 <a id="browsing-another-branch"></a>

タイトルバーのブランチは、ローカルとリモート追跡のすべてのブランチを新しいコミット順
に並べたメニューを開き、選ぶとそのブランチの履歴を表示します。読むだけの覗き見です。
gitty は `checkout` を実行しないので、ワークツリーもその差分もターミナルも git が残し
た場所のままです。別のブランチを見ている間、タイトルバーは `⎇ main › other-branch` と
表示され、コミットペインはどのブランチを並べているかを述べます。
**Back to \<branch\>** で戻ります。各タブは独立して閲覧します。

#### Push と Pull <a id="push-and-pull"></a>

**Push** と **Pull** はヘッダーにあり、ログがどのブランチを向いていても、両方ともチェッ
クアウト中のブランチに作用します。**Push** は未プッシュの数を数え — **Push 3** — 送る
ものが無ければ灰色になります。追跡していないブランチでは、そのブランチを `origin` に公
開して上流を設定します。**Pull** は上流から早送りし、上流が無ければ灰色です。git が
言ったことはログの上に出ます — クリックで消え、失敗は消すまで残ります。

どちらもプロンプトには答えられません。背後にターミナルが無いので、パスワードやパスフ
レーズを求める push はぶら下がらずに git 自身のメッセージで失敗し、早送りできない
pull もそう言います。その後はどちらもすぐ隣のターミナルペインで手作業で片付けます。

### Terminal (右下) <a id="terminal-bottom-right"></a>

リポジトリをルートとする本物の対話的ログインシェル (`$SHELL`) なので、どんな git コマ
ンドも直接実行できます。<kbd>Ctrl+Shift+C</kbd> はターミナルの選択範囲をコピーします
— そこの <kbd>Ctrl+C</kbd> は割り込みで、割り込みのままです。同じコードは他のどのペ
インでもコピーなので、フォーカスが移っても意味が変わりません。リポジトリがディスク上
で変われば、他のペインは自動的に更新されます。どのシェルで始めるか、ログインシェルと
して始めるかは [設定](#settings)です。どちらもターミナルの生成時に読まれるので、変更
は次の分割から効きます。

このペインは好きなだけシェルに分割できます。**Split →** はフォーカス中のターミナルの
隣に、**Split ↓** はその下に新しいものを置き、間の仕切りは他のペインと同様にドラッグ
できます。ターミナルをクリックするとフォーカスされ — 輪郭が付いたものが次の分割や
**Close** の着地点です。同じ方向に 2 回分割すると入れ子にならず行や列が伸びるので、横
並びの 3 つのターミナルは互いにサイズを融通し合います。

**Close** はフォーカス中のシェルを終わらせます。`exit` でシェルを抜ければその分割は自
分で閉じます。最後のターミナルは常に残ります。それを終了しても、空のペインではなく画
面に通知が残ります。

## テキストの検索 <a id="finding-text"></a>

<kbd>Ctrl+F</kbd> は右側のペインに表示中のものなら何でも検索します。差分、ファイル、
描画済み Markdown ドキュメント、[HTML プレビュー](#html-preview)、blame、ファイルの
履歴です。一致箇所はすべてハイライトされ、現在のものが際立ち、<kbd>Enter</kbd> と
<kbd>Shift+Enter</kbd> (または矢印キー) で移動して両端で折り返し、件数が現在地を示
し、<kbd>Esc</kbd> で閉じます。

検索は大文字小文字を区別せず、背後にあるマークアップではなく描画後のテキストを読みま
す — だから Markdown が内部に残す太字やコードスパンをまたいで語句が見つかり、差分は
見えている行として検索されます。スクロールに応じてかたまりで描画するビュー (長いファ
イル、大きな差分) は、検索バーが開いたときに残りを描画するので、件数はこれまでスク
ロールした分だけでなく全体を覆います。複数ファイルの差分で折りたたまれたファイルは折
りたたまれたままで、検索されません。

## 設定 <a id="settings"></a>

タイトルバーの **Settings**、または <kbd>Ctrl+,</kbd>。ここの内容はすべてのタブに適用
され、再起動をまたいで記憶されます。**Restore Defaults** ですべて元に戻ります。ダイア
ログは **Appearance**、**View**、**Session** の 3 つのタブに分かれていて、増えても 1
画面に収まります。下の表はその順で並べています。

| | |
| --- | --- |
| **Theme** | Dark か Light。 |
| **Language** | English、简体中文、日本語、한국어、Français、Deutsch、Español、Русский、Português — インターフェース、メニュー、ダイアログがすべて再起動なしで切り替わります。 |
| **Time zone** | 画面上の日時がすべてどのゾーンで描画されるか。既定はマシン自身のゾーン、または UTC、あるいはシステムが知る任意のゾーン。git は各コミットを作者のオフセット付きで記録するので、タイムスタンプは常にゾーンの選択です — ここでそれを決めます。ログの日付列がそれに従い、つまり「今日」と日付の境目も一緒に動きます。 |
| **Time format** | Absolute (時刻または日付) か Relative (`28m ago`、`2h ago`)。Relative はゾーンの問題を完全に迂回します。行のホバーヒントはどちらでも絶対表示のまま、そのゾーンを名指しします。 |
| **Font size** | 9 – 20、0.5 刻み。ターミナルを含むすべてのペインに適用。 |
| **Monospace font** | ペインとターミナルを描くファミリー。このマシンで見つかった等幅フォントから選びます。**System default** は組み込みのスタック (JetBrains Mono、Fira Code、DejaVu Sans Mono、…) です。 |
| **Row height** | 18 – 26 ピクセル。ファイルツリー、ログ、差分など、あらゆるリストが土台にする行の高さです。詰めれば画面に多く入り、緩めれば読みやすくなります。 |
| **Diff layout** | Inline か Side-by-Side。差分ヘッダーのトグルと同じものです。 |
| **Context lines** | 各 hunk の前後の変更されない行を 0 – 25。git の `-U` で、既定は 3。広げれば変更が何の中にあるかが見え、狭めれば大きな差分を画面により多く収められます。 |
| **Ignore whitespace** | Off、Amount (git の `-b`。長さが変わるだけの連続スペースは変更ではない)、All (`-w`。空白の違いは一切変更ではない)。再インデントや折り返し直しのコードは赤緑の壁ではなく、変更なしと読めます。ファイルリストの `+12 −3` の数も同じ設定に従うので、差分が表示を拒む行を数え上げることはありません。 |
| **Word wrap** | 横スクロールの代わりに長い行を折り返す。 |
| **Word highlight** | 変更行のうち変わった語を、行全体ではなく語単位で示す。 |
| **Markdown outline** | 描画済みドキュメントの脇にアウトラインを表示。 |
| **Markdown source lines** | 描画済みドキュメントの各ブロックに、ソースで始まる行番号を付ける。見出し・段落・リスト項目・表・フェンス付きコード・画像すべてが、左に下りるガターに番号を持ちます。既定はオフ。 |
| **File sorting** | Natural か Byte order。Natural は名前の中の数字を数値として読み (`W9` を `W10` の前に)、大文字小文字を二の次にします。byte order は git 自身のもので、すべての大文字がすべての小文字の前に並びます。 |
| **Reopen last session** | 前回アプリを終了したときに開いていたリポジトリを開き直す。Gitty を起動したリポジトリは依然としてアクティブなタブで、その後削除されたものは静かに落とされます。 |
| **Shell** | ターミナルが始めるシェル。`/etc/shells` と通常のパス (Windows では `COMSPEC` と PowerShell) から列挙されます。**System default** は `$SHELL`。その後消えたパスは、死んだペインを残すのではなくそれへフォールバックします。 |
| **Login shell** | `-l` 付きで始めるので、ユーザーのプロファイルが読み込まれます。オフにすると、より速く静かなシェルに — プロファイルの出力もログイン時のチェックもありません。Windows のシェルにはそのフラグがなく、これは無視されます。 |

**Shell** と **Login shell** はターミナルの生成時に読まれるので、既に走っているシェル
ではなく次の分割や次のリポジトリタブから効きます。**Word wrap**、**Diff layout**、
**Markdown outline** は差分ヘッダーのトグルと同一なので、どちらで変えても両方に効きま
す。**Word highlight** はここにしかありません。

## プラットフォームに関する注記 <a id="platform-notes"></a>

### Linux デスクトップ統合 <a id="linux-desktop-integration"></a>

下の 2 つの妥協には同じ原因があります — パッケージ化されずに*実行される* Electron ア
プリ — なので、どちらも `.deb` では消え、どちらも `setup.sh` の経路には残ります。そ
れは本当に未パッケージの Electron を実行しているからです。

**ウィンドウクラス。** `setup.sh` が書くデスクトップエントリは
`StartupWMClass=electron` を持ちます。アプリが自分を何と名乗ろうと、未パッケージの
Electron が報告するのはこの値で、ウィンドウ一覧とドックはウィンドウのアイコンを見つけ
るためにこれと突き合わせます。副作用は、同じセッションの別の未パッケージ Electron ア
プリが Gitty のアイコンを借りることです。パッケージ化されたビルドは独自の実行ファイル
を持つので、そのエントリは `gitty` に一致し、衝突は起こりません。

**サンドボックス。** `run.sh` と `cli.js` は `ELECTRON_DISABLE_SANDBOX=1` を設定しま
す。`chrome-sandbox` は `node_modules` の中に root 所有の setuid ビットを保てないから
です。`.deb` には回避すべきものはありません。その `postinst` は、非特権ユーザー名前空
間の無いカーネルではヘルパーを 4755 にし、名前空間サンドボックスが動く場所では 0755 の
ままにし、Ubuntu 24.04 が求める AppArmor プロファイルをインストールします。つまりパッ
ケージからインストールしたものは、サンドボックスが有効です。

`.AppImage` は 2 つのうち弱い方です。setuid ビットを運べるものは何もないので、非特権
ユーザー名前空間に依存します — これは Ubuntu 24.04 の AppArmor ポリシーが既定で制限し
ています。そこでは `--no-sandbox` を渡すか、自分で AppArmor プロファイルをインストー
ルすることを想定してください。可能なところでは `.deb` を選んでください。

### macOS アプリケーションバンドル <a id="macos-app-bundle"></a>

`Gitty.app` はパッケージではなくラッパーです。`Contents/MacOS/Gitty` は
`run.sh --fg --any` を exec する 2 行のスクリプトです。`--fg` が重要で、最後まで exec
し通すことで Dock のタイルがバンドルに留まり、プロセスがそれを生き延びて孤立することが
ありません。また `--any` によって、Finder からの起動（カレントディレクトリが無い）でも
直近に開いたリポジトリにフォールバックします。

名前は現れる 3 箇所すべてで正しく、そのうちバンドル由来なのは 1 つだけです。Finder と
Dock は `Info.plist` から `CFBundleName` と `CFBundleIconFile` を読みます。メニュー
バーは `app.name` で、ウィンドウができる前に `app.setName('Gitty')` が設定し、
`{ role: 'appMenu' }` がそのラベルとして使います。ですので、上記の Linux のウィンドウ
クラスの問題とは違い、ここには妥協点がありません — パッケージ化で得られるものは署名だ
け、そして `electron-builder.yml` が Linux ターゲットだけを設定しているのもそのためで
す。

Finder から起動されたバンドルは launchd の最小限の `PATH` を引き継ぎ、nvm も Homebrew
も載っていません。そして `run.sh` はバンドルが古くなったときに再ビルドするため `node`
と `npm` を必要とします。`setup.sh` はインストール時にそれらを解決して先頭に追加します
— プレフィックスなので、ターミナルからの起動には影響しません。後で Node のバージョン
を切り替えた場合、そのパスは古くなります。`setup.sh` を再実行して指し直してください。
