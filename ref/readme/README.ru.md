Настольный браузер истории git с четырьмя панелями, в духе `lazygit`, но с настоящим
взаимодействием мышью: двойной щелчок открывает файл, правый щелчок копирует его путь,
щелчок по двум коммитам сравнивает их.

```
┌──────────────────────┬──────────────────────┐
│ Changes              │ Diff                 │
│ (or a commit's files)│ (unified, coloured)  │
├──────────────────────┼──────────────────────┤
│ Commits              │ Terminal             │
│ (log, ↑↓, Enter)     │ (a real shell)       │
└──────────────────────┴──────────────────────┘
```

Размер всех панелей меняется перетаскиванием разделителей, а каждую можно скрыть и
вернуть — см. [Полный экран и скрытие](manual.ru.md#full-screen-and-hiding).

То, чего большинство других git-браузеров не делают:

- **Настоящий shell, пристыкованный к истории.** Не виджет, вызывающий git, а подлинный
  login-shell (`$SHELL`), корнем в репозитории, в том же окне, что и diff, и делящийся
  на несколько. Большинство git-браузеров либо не имеют терминала вовсе, либо запускают
  внешний, так что проверить догадку — значит переключаться между окнами. Здесь он прямо
  тут, и все остальные панели обновляются вместе с изменениями репозитория.
- **Индексация, которая заканчивается агентом, а не полем для сообщения.**
  Проиндексируйте файл, hunk или только выделенные строки; затем **Send** впечатает
  вашу собственную команду — `claude "commit the staged changes"`, `codex exec …`,
  что бы вы ни запускали — в shell внизу и нажмёт Enter. Писать сообщение — работа
  агента. Решать, *какие изменения образуют один коммит*, — ваша, и именно для
  этого четыре панели. Изнутри Gitty не вызывается ни одна модель, так что ничего
  не покидает машину без вашего участия.
- **Документы, а не только diff.** Markdown отрисовывается, HTML показывается в
  изолированном фрейме, изображения показываются как картинки — всё на той ревизии, где
  вы находитесь. README двухлетней давности отрисовывается со скриншотами, которые
  поставлялись *тем* коммитом, читаясь напрямую из базы объектов — на диске ничего не
  задействовано, и из сети ничего не загружается, потому что чтение чужого README не
  должно выдавать вас тому хосту, на который оно ссылается.
- **Отрисованный markdown, который по-прежнему говорит, где вы в файле.** Включите
  **Markdown source lines** — и каждый заголовок, абзац, элемент списка, таблица, блок
  кода и изображение нумеруются в желобе строкой, с которой они начинаются в исходнике, —
  так фрагмент, найденный при чтении, можно править построчно.
- **Diff, blame, история файла и отрисованный README — открыты одновременно.** Файлы
  открываются своими вкладками *рядом* с diff, а не поверх него, и каждый помнит ревизию,
  на которой был открыт. Чтение файла никогда не лишает вас изменения, на которое вы
  смотрели.
- **<kbd>Ctrl+F</kbd>, который работает в том, что показывает панель**, — в том числе в
  отрисованном markdown, где фраза находится поперёк жирных и кодовых участков, потому
  что поиск читает отрисованный текст, и внутри фрейма HTML-предпросмотра.
- **История, отданная вашему браузеру.** **Open in Browser** передаёт коммит — его
  метаданные, его файлы, его diff — системному браузеру, из веб-сервера внутри приложения,
  привязанного к `127.0.0.1`, — вашему собственному браузеру и ничьему больше. Коммиты —
  настоящие URL, так что историю можно читать во вкладках, держать открытой и искать
  собственным поиском браузера, пока репозиторий открыт.
- **[gource](https://gource.io/) из меню коммитов**, если он установлен: вся
  история репозитория как анимация, в собственном окне. Если gource отсутствует,
  пункт не рисуется — ничего не скачивается и не предлагается того, что не может
  запуститься.
- **Девять языков интерфейса и явный часовой пояс.** Git записывает каждый коммит со
  смещением его автора, так что метка времени — всегда выбор пояса; здесь его делаете вы,
  и весь интерфейс — журнал, blame, история файла, граница между «сегодня» и датой —
  следует за ним.

## Зачем ещё один? <a id="why-another-one"></a>

Потому что каждый инструмент, за который я брался, ошибался в чём-то одном:

- **IDE** — слишком тяжёлые и слишком медленные. (Поверьте, я перепробовал все, какие
  смог найти.)
- **lazygit, grv** — отличные инструменты, но недружелюбны к мыши и к выделению текста.
- **gitui** — я хочу видеть список коммитов и diff на экране одновременно.
- **SmartGit, GitKraken** — Java, тяжесть, устаревший вид, и они хотят ваших денег.
- **gitg** и компания — опять же, нет списка коммитов и diff рядом.
- **tig** — только diff, нет дерева файлов для просмотра.
- **gitk** — уродлив!

И ещё две вещи, которые я хотел и которые почти никто не предлагал: **предпросмотр
markdown** и **копирование-вставку, которая просто работает** в любом месте окна.

## Требования <a id="requirements"></a>

- Node.js 20 или новее
- `git` в `PATH`
- Linux, macOS или Windows с графическим сеансом
- Опционально [gource](https://gource.io/) в `PATH` для [анимации](manual.ru.md#gource); если его
  нет, ничего не меняется

## Запуск <a id="running"></a>

### Скачать пакет (Linux) <a id="download-a-package-linux"></a>

`.deb` — самый короткий путь: ни Node, ни сборки:

```bash
wget https://github.com/baojie/gitty/releases/download/v0.2.0/gitty-desktop_0.2.0_amd64.deb
sudo dpkg -i gitty-desktop_0.2.0_amd64.deb
```

Он ставит `/usr/bin/gitty`, запись в меню приложений со значком, и работает с
песочницей Chromium **включённой** — см.
[Интеграция с рабочим столом Linux](manual.ru.md#linux-desktop-integration).

Рядом лежат [`.deb` для arm64](https://github.com/baojie/gitty/releases/download/v0.2.0/gitty-desktop_0.2.0_arm64.deb)
и AppImage для дистрибутивов без dpkg
([x86_64](https://github.com/baojie/gitty/releases/download/v0.2.0/Gitty-0.2.0-x86_64.AppImage),
[arm64](https://github.com/baojie/gitty/releases/download/v0.2.0/Gitty-0.2.0-arm64.AppImage)) —
это второй выбор, потому что AppImage не может установить помощник песочницы. Более
старые версии — на [странице релизов](https://github.com/baojie/gitty/releases).

### Из npm <a id="from-npm"></a>

```bash
npm install -g gitty-desktop      # installs the gitty command globally
```

### Из клона <a id="from-a-checkout"></a>

Прилинкуйте её в PATH так:

```bash
./setup.sh               # symlink into ~/.local/bin (no sudo)
./setup.sh --system      # symlink into /usr/local/bin (needs sudo)
```

`setup.sh` также ставит кликабельный лаунчер — запись рабочего стола в Linux,
минимальный `Gitty.app` в macOS. Оба оборачивают один и тот же `run.sh`, и оба несут
обходные пути, нужные непакетированному Electron; см.
[Заметки о платформах](manual.ru.md#platform-notes).

Затем откройте репозиторий откуда угодно:

```bash
gitty                    # open the repository in the current directory
gitty /path/to/repo      # open another repository
gitty --fg               # keep it attached to the terminal (Ctrl+C quits)
gitty --dev              # hot-reloading development mode
gitty --any              # start even outside a work tree (what the desktop
                         # entry uses), falling back to the last repositories
```

Gitty отсоединяется от терминала и печатает свой pid, так что shell остаётся пригодным,
а его закрытие не сносит окно. Вывод идёт в
`${XDG_STATE_HOME:-~/.local/state}/gitty/gitty.log`, который обрезается до последнего
мегабайта, как только превышает 4 МБ.

`./run.sh` — тот же скрипт и работает идентично без симлинка. Лаунчер ставит зависимости
и пересобирает бандл при изменении исходников, так что первый запуск может занять
минуту. `npm run dev`, `npm run build` и `npm start` тоже доступны напрямую.

Запуск Gitty из каталога вне рабочего дерева откатывается к последнему открытому
репозиторию, вместо того чтобы просто ругаться.


## Чего Gitty не делает <a id="what-gitty-does-not-do"></a>

Gitty читает историю и индексирует (stage) то, что вы решаете собрать вместе. Он не
делает rebase, merge, cherry-pick, не разрешает конфликты и не создаёт, не удаляет и
не переключает ветки — и не научится. Это операции с состоянием и в несколько шагов,
чьи интересные моменты — те, где что-то идёт не так, а shell, который всё это умеет,
пристыкован в том же окне, уже в нужном каталоге. Половина кнопки rebase хуже, чем
никакая.

Коробки для коммита тоже нет, и это меньшее заявление, чем кажется. Не хватает не
сообщения: не хватает места, где решать, *какие изменения образуют один коммит*, — и
именно для этого нужна индексация выше. Как только индекс сказал одно,
**Send** передаёт это тому, что пишет ваши сообщения.

## Архитектура <a id="architecture"></a>

```
src/main       Electron main process — git commands, ptys, fs watchers,
               the recent-repository store, IPC
src/preload    contextBridge API exposed to the renderer as window.gitty
src/renderer   React UI — App.tsx manages tabs, RepoTab.tsx owns one
               repository's four panes
src/shared     Types shared by both sides
build          Application icon (SVG source and rendered PNG)
```

Git вызывается через `execFile('git', …)` с разбором `--porcelain=v2 -z` /
`--name-status -z`, так что пути с пробелами и переименования выживают. Никакая git-библиотека
не встраивается; какой `git` в `PATH` — тот вы и видите. Рендерер работает с
`contextIsolation` и без node-интеграции.

Рендерер разбит на лениво загружаемые чанки, так что окно рисуется раньше, чем разобраны
xterm, highlight.js и markdown-it. Это разбиение — четыре чанка, правила, как не пускать
тяжёлые библиотеки в тёплые, и как добавить новый, — описано в
[ref/spec/lazy-loading.md](../../ref/spec/lazy-loading.md).
